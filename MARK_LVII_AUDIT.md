## Architecture and dependencies

- `main.py` owns the Gemini Live session, audio streams, tool dispatch, and background-thread event loop; `ui.py` and `gui/` own the PyQt6 window and HUD on the Qt main thread. `AGENTS.md` specifies these threading boundaries.
- `core/gemini.py` centralizes one-shot Gemini calls and model fallback. `providers/` holds a lazily loaded STT → LLM → TTS alternative with one OpenAI-compatible LLM implementation. `memory/config_manager.py` stores provider choices and keys in ignored `config/api_keys.json`.
- `memory/memory_manager.py` stores facts and session summaries in ignored `memory/long_term.json`, with lexical recall and a bounded prompt excerpt. `core/tasks/` persists checkpointed background jobs in JSON. `core/routines/` stores and schedules routines.
- `core/action_loader.py` discovers `actions/*.py`; `core/plugin_loader.py` discovers drop-in `plugins/*.py`. `dashboard/server.py` serves the companion phone interface and authenticated commands over FastAPI/WebSocket.
- Direct dependencies include PyQt6, sounddevice, NumPy, google-genai, httpx, requests, Playwright, pyautogui, OpenCV, FastAPI, cryptography, and document parsers. Optional local voice components include faster-whisper, Piper, and openwakeword. These desktop packages are not Android dependencies and cannot be copied into a lightweight Kotlin app.

## Android 11 wake-word finding

Android 11 requires a microphone foreground-service type for microphone access in a foreground service, and a service started while the app is already in the background cannot gain microphone access. Therefore Stage 1 should ship push-to-talk only; a wake-word implementation needs a visible, user-started session, an ongoing notification, battery measurement on the Redmi 9A, and an explicit privacy control. Upstream openWakeWord provides a `hey_jarvis` TFLite model, but its checked-in integration is Python and is not itself an Android SDK. See [Android 11 foreground-service rules](https://developer.android.com/about/versions/11/privacy/foreground-services), [Android SpeechRecognizer API](https://developer.android.com/reference/android/speech/SpeechRecognizer), and [openWakeWord upstream](https://github.com/dscripka/openWakeWord).

## Baseline verification and limits

- `git status --short` on the temporary upstream checkout was empty. No upstream files were edited.
- The host has Python 3.9.7; AST parsing found 95 parseable Python files and one version-specific parse failure in `providers/_tests.py:286` (`except*`, Python 3.11 syntax). This is a toolchain mismatch, not evidence of a repository defect under its intended Python version.
- The Mac currently exposes no Java runtime, Gradle, Android Studio, Android SDK, or `adb` in common installation locations. Android build and device tests require those tools and the user’s device or emulator.
- Feature presence was verified by source inspection. API calls, audio devices, desktop automation, and the phone dashboard have not been exercised because credentials, desktop Python dependencies, and device access were not available.
